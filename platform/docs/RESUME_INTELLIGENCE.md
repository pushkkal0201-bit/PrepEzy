# Stage 10 — Resume Intelligence: design and verification

### Real parser

- Input: explicit multipart upload to /api/local/resume/upload; accepted PDF, DOCX, UTF-8 TXT and Markdown, max 2 MiB.
- PDF: pypdf parses selectable text, at most 8 pages. Original page numbers retained. No OCR or invented image transcription.
- DOCX: python-docx reads paragraphs and table cell text; ZIP member count and expanded-byte caps reduce accidental decompression risk. This is not a certified malicious-file sandbox.
- Text: UTF-8 only; binary bytes and empty/impossibly small text fail.
- A single local resume record stores SHA-256, filename, extracted text lines, location labels and import time in PREPEZY_LOCAL_DB. Raw uploaded bytes are not persisted. This database may contain personal information: keep on your own trusted device only.

### Inspection semantics

Detected section headings, literal technology keywords, email presence and portfolio URL presence are document-structure hints, **not a hiring-grade test**. Each technical mention includes exact extracted quote + page/document location and line. A missed keyword may simply be phrased differently or visually inaccessible. Do not treat it as missing experience.

### Role-specific matching

The selected job comes only from the CareerEngine job snapshots generated by explicit Greenhouse/Lever refresh. PrepEzy compares extracted resume mentions against that job's extracted requirement tags. Independently assessed UnifiedEvidence SkillGraph outcomes remain a separate section, never added as a claim the resume proved. Next actions suggest honest review of unmentioned requirements, genuine additional practice for unassessed skills and the currently available PrepLoop exercises. No invented ATS percentages, unsupported achievements, external LLM forwarding or auto-applying.

### API endpoints

GET /api/local/resume/status
POST /api/local/resume/upload
GET /api/local/resume/inspection
GET /api/local/resume/jobs/{job_id}/analysis
DELETE /api/local/resume

DELETE /api/local/data also purges the resume record. Only one local document is retained at a time; importing a new file replaces the prior extracted text.

### Security / follow-on

Never publicly deploy while authentication is deferred. Ensure local SQLite is stored outside your Git repository. Future security work: malware-aware parsers in separately isolated processes, consent-led multi-user document access, test against nontrivial multi-column layouts, optional on-device OCR, quantified extraction accuracy, verified claim documentation, employer-specific evidence briefs and optional export to an editable format.
